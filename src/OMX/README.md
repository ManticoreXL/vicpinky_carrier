## 추론 및 제어 흐름
본 프로젝트의 제어 및 추론 시스템은 로봇의 실시간 제어(라즈베리파이)와 딥러닝 연산(Host PC)이 서로 병목을 일으키지 않도록 **비동기 분산 아키텍처** 로 설계 

전체 추론 루프는 철저하게 이벤트 기반(Event-driven)으로 동작, 하드웨어 자원의 충돌을 막고 네트워크 지연을 최소화하는 데 중점

### 1. 초기화 및 모니터링 대기
> 시스템이 가동되면 추론 연산 대기 상태를 유지, 시각 및 통신 인프라 우선 구축
> #### 센서 노드 가동
> - 전면 및 손목 카메라가 별동의 스레드로 즉시 가동되어 프레임 수집
> #### 프로세스 격리
> - Flask 웹 서버는 multiprocessing을 통해 메인 프로세스와 완전히 격리
> - UI 렌더링 부하가 로봇 제어 루프에 영향을 미치는 것을 차단
> #### 통신망 구축
> - OmxStateNode (ROS2) 가 활성화되어 외부 시스템으로부터 추론 시작 토픽을 대기

### 2. 추론 시작 및 자원 매핑
> ROS2 토픽을 통해 특정 작업 명령이 수신되면 본격적인 제어 시작 
> #### 상태 전이
> - OmxStateNode가 신호를 수신하면 해당 작업에 맞는 사전 학습 모델을 동적으로 매핑
> - 대기 중이던 추론 루프에 start_event를 발생시켜 엔진을 기동
> #### Device Resource Hooking
> - LeRobot 추론 모듈이 프레임을 요구할 때, 실제 카메라 하드웨어를 다시 호출하면 리소스 충돌 발생
> - 이를 해결하기 위해 비전 스레드가 실시간으로 갱신해둔 공유 메모리에서 최신 프레임을 꺼내어 사용

### 3. 분산 추론 및 제어
> 라즈베리파이의 연산 한계를 극복하기 위해 제어와 추론을 물리적으로 분리하여 수행
> #### gRPC 기반 네트웨크 오프로딩
> - runpy를 통해 백그라운드에서 실행된 LeRobot Client는 획득한 30 FPS 카메라 프레임을 TCP/IP 네트워크를 통해 GPU 서버로 전송
> #### Action 수신 및 구동
> - GPU 서버에서 계산된 관절 제어 명령을 반환받아 로봇팔의 모터를 제어. 제어 루프는 24 FPS 수준으로 반복

### 4. 비전 기반 실시간 상태 평가
> 시스템이 작동하는 동안 비전 스레드는 환경 변화를 실시간 분석
> #### 관심 영역 분석
> - 전면 카메라 프레임 내에서 HSV 색공간 변환을 통해 색체의 유무,중심점 도달 여부, 적재 위치 영역의 상태를 병렬로 계산
> #### 타이머 기반 노이즈 필터링
> - 순간적인 조명 변화나 로봇팔에 의한 가려짐으로 인한 오작동을 막기 위해, 특정 감지가 실정 시간 이상 지속되어야만 유효한 상태 변화로 확정
> - 결과는 즉시 ROS2 토픽으로 발행되어 시스템 전반에 전파

### 5. 자율 종료 및 안전 제어
> 작업이 완료되거나 특정 조건이 만족되면 시스템이 스스로 상황을 판단하여 제어 루프를 안전하게 종료
> #### 종료 조건 판별
> - 비전 스레드에러 물체가 적재 구역에 도달(LOADED)하고 중심 위치에 정렬(Center ON)된 두 가기 조건이 동시에 충족되면 목표 달성으로 판단
> #### Watchdog 강제 중지
> - 노드가 stop_event를 발생시키면, 대기 중이던 Watchdog 스레드가 즉각적으로 인터럽트를 호출하혀 무한 반복되던 비동기 추론 루프를 즉시 중단
> - 이후 상태 변수를 초기화하고 새로운 외부 명령을 기다리는 대기 상태로 복귀
